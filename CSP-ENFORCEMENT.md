# Enabling enforced CSP after staging verification

This upgrade intentionally ships **Content-Security-Policy-Report-Only** in `proxy.ts`. No production or staging deployment was performed. Do not rename the header until these checks are complete.

1. Deploy a reviewed version to an authorized staging/preview environment. Inspect CSP violations in browser developer tools while opening the standalone page and the actual Sites embedded preview. If using a reporting endpoint, configure an explicit first-party endpoint and retention policy; the current policy does not transmit reports anywhere.
2. Record the exact Sites parent origin(s) seen in that environment. In `proxy.ts`, extend `frame-ancestors 'self'` with only those verified origins. Do not use `*`, `frame-ancestors 'none'`, or X-Frame-Options DENY. Check auth navigation using the existing `target="_top"` link.
3. Keep `THEME_HASH` from `lib/theme.ts` in `script-src`. Inventory all framework inline scripts and verify the installed Vinext version supports propagating request nonces to its generated scripts; if supported, use fresh cryptographic per-response nonces and matching CSP sources. Otherwise add hashes for exact stable scripts and resolve dynamic scripts before enforcing. Remove `'unsafe-inline'` from `script-src` only after all required scripts have valid sources. A script hash makes modern browsers ignore the current `'unsafe-inline'` fallback, so report-only violations are expected until framework coverage is complete. Never add `'unsafe-eval'` simply to silence development-only reports in the release policy.
4. Verify the complete standalone and embedded flows: public home/type/tag/search/article pages, dark/light reload, owner login/sign-out and hydrated chrome, private editor/autosave/preview, uploads, publish/schedule, Markdown imports/downloads, bookmarks/progress, copy/share/print and manage actions. Allow only demonstrated required `connect-src`, script, style, image, font or frame sources. Current styles still permit inline styles for existing editor/UI behavior. If nonces depend on requests, review the public HTML cache design before changing it.
5. After all required flows pass with no unexplained violations, change only the header name in `proxy.ts` from `Content-Security-Policy-Report-Only` to `Content-Security-Policy`, retain the verified policy, run all four checks in README.md, deploy the reviewed change, and repeat standalone/Sites iframe verification. Revert to report-only immediately if a required flow is blocked.

HSTS is independent: inspect HTTPS response headers from the hosting edge before adding an application Strict-Transport-Security header. Do not duplicate or weaken an existing edge policy.
